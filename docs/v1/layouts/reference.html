Gateway API

The uniform interface every site gateway answers — status · readings · health. Because the interface is the same at every site, the hub treats «Måkeholmen» and «Ternebåen» identically.

Summary

At a glance

Verbsstatus · readings · health — all three required
Implemented byEvery site gateway, regardless of its sensor mix
TransportHTTPS from the hub; local socket on the gateway itself
IdempotentYes · all three verbs are read-only
AuthMutual TLS between gateway and hub; the API adds none

A gateway answers the same three verbs whether it fronts two sensors or twenty — the hub cannot tell, and does not need to. That is the whole point of the gateway pattern here.

Verb 01

status

Describe what this gateway is and what it fronts, without returning any readings. The hub polls status to plan collection.

FieldTypeRequiredNotes
sitestringyesLocality slug, e.g. maakeholmen
ownerstringyesFunction on the rota in «Vaktlista»
sensorsstring[]yesSensor kinds this gateway fronts
alertsstring[]noOpen alert ids raised in «Strømvarsel»
bufferobjectoutage onlyPresent while readings are queued locally

Verb 02

readings

Answer a window of readings from this gateway's sensors. During an outage the gateway serves from its local buffer and replays on reconnect — store-and-forward, publish–subscribe on top.

readings · request / responsejson
// request{ "site": "maakeholmen", "sensors": ["oksygen"], "limit": 20 }// response — a flat list, provenance on every reading{ "readings": [  { "site": "maakeholmen", "sensor": "oksygen-3", "value": 8.4 }] }
Buffered
During an outage the gateway keeps serving from its local disk buffer; the hub replays the gap oldest-first on reconnect.
Provenance
Every reading carries its site and sensor so the caller knows exactly where it was measured.
Partial
If a sensor is down, its readings are omitted — the request still returns.

Verb 03

health

Report whether this gateway and its sensors are fit to trust. This is the verb «Strømvarsel» watches.

Input<site>/<sensor> — e.g. maakeholmen/oksygen-3; omit the sensor for the whole gateway
ReturnsState, last-seen timestamp, buffer depth, and per-sensor detail
On missReturns null — the caller shows «ukjent», never a false green

Contract edges

Failure modes

SituationBehaviourCaller sees
Unknown sensorhealth returns null«Ukjent» state
Sensor times outGateway omits its readingsPartial window
Missing verbGateway rejected at enrolmentNever joins the hub
Clock driftHub restamps, logs the skewReading + warning

Never let a read verb mutate gateway state. All three verbs are read-only; restarts and configuration changes go through the on-call procedures owned by Drift in «Vaktlista».
