Restart a stuck site gateway

The recovery pass for a gateway that has stopped forwarding after a power or network outage. Store-and-forward means nothing is lost — the buffer replays once the service is back.

Trigger

When to run this

Restart is idempotent, never destructive. The buffer lives on disk and survives the restart; queued readings replay to the hub in order. This runbook is safe to run at any time — it cannot drop a reading.

«Strømvarsel» alert
The «gateway silent» alert fires when the hub has heard nothing for 15 minutes. Start here.
After a site outage
Run by hand once power or the link is back, if the gateway has not resumed forwarding on its own.
After maintenance
When Vedlikehold has had the cabinet open, a manual restart confirms the service came back cleanly.

Step 1

Pre-flight checklist

Confirm all four before starting. If any fails, resolve it first — do not force past a red check.

  • Alert confirmed in «Strømvarsel»

    The alert names this gateway and is still open — you are fixing the right site.

  • Link is back up

    The gateway answers ping from the hub; if not, this is a network fault, not a stuck service.

  • Buffer disk has room

    gw disk shows the buffer partition under 90% — a full disk needs escalation, not a restart.

  • You can reach the console

    SSH to the gateway works, or the site technician on «Vaktlista» is on the line.

Step 2

Run the restart

One command. It stops the forwarder, verifies the buffer index, and starts the service again — the buffer itself is never touched.

terminalbash
# check first — prints service and buffer state, changes nothinggw status --verbose# then, the restartgw restart forwarder

Never pass --flush. Flushing drops the buffer, and the outage window's readings with it. The whole point of store-and-forward is that the replay happens on its own.

Step 3

Confirm the outcome

ExpectedForwarder reports «running»; «Strømvarsel» clears the alert within one poll cycle
BackfillBuffer depth falls steadily; the hub shows the outage window filling in oldest-first.
Runtime≈ 2–10 min depending on buffer depth. A stall usually means the hub is throttling the replay.

Green. The alert is closed, the buffer is at zero, and the outage window is complete in «Bøyeloggen». Note the restart in the shift log — your job is done.

If it goes wrong

Rollback

Because the restart is idempotent and the buffer survives it, rollback is just running it again — nothing is deleted at any step.

  1. Restart again. A second gw restart forwarder is always safe; replay resumes from the buffer index.

  2. Fix the cause. A gateway that sticks twice after the same outage almost always has a failing buffer disk — check it before the next storm.

  3. Re-check «Strømvarsel». Confirm the alert closed and no new one fired before you sign off.

Escalate to Vedlikehold only if the hardware itself won't come up — a stuck service is always recoverable from the console and never needs a site visit on its own.
