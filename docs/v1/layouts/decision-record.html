Buffer readings at the edge

Site gateways store readings locally and forward them when the shore link allows — store-and-forward — rather than streaming straight to the hub and losing whatever the link can't carry.

Why now

Context

After a season of operation, gaps in «Bøyeloggen» clustered around storms — exactly when readings matter most. The sensors kept measuring, but stream-only gateways dropped whatever the shore link couldn't carry, so HMS thresholds in «Strømvarsel» fired late or not at all, and no one on «Vaktlista» was paged.

One constraint ran through the whole discussion: no reading may depend on the shore link being up. Whatever we decide must hold on the gateway hardware alone.

What we decided

Decision

Every site gateway buffers readings locally and forwards them when the link allows — store-and-forward, with the hub as the single subscriber per site.

  1. Sensors publish locally. Each instrument publishes to its site gateway over the site network — plain publish–subscribe, never a direct line to shore.

  2. The buffer comes first. Every reading lands in the gateway's local store before any forward attempt is made.

  3. Forwarding is ordered and idempotent. The backlog drains oldest-first; the hub deduplicates on site · sensor · timestamp.

  4. Alerts evaluate at the edge. «Strømvarsel» thresholds run on the gateway too, so «Vaktlista» still pages the on-call during an outage.

The road not taken

Options considered

OptionWhy not
Stream-only to the hubAny link drop loses readings; the storm-gap problem never gets solved. The gaps land precisely on the readings HMS needs.
Buffer at each sensorDozens of tiny stores per site to operate; the instruments lack the storage and battery to hold a real backlog.
Redundant shore links per siteReduces outages but can't eliminate them — a mediator that still fails whole. Doubles network cost without removing the loss mode.

What follows

Consequences

✓ We gain
  • No readings lost to shore-link outages.
  • The hub sees one ordered stream per site.
  • Edge alerts keep working when a site is cut off.
  • New sensors join by publishing to the gateway — the hub is untouched.
✕ We accept
  • Gateway storage to size and monitor.
  • Backlog drain competes with live readings after long outages.
  • Vedlikehold owns one more box per site.
  • Dashboards can lag reality while a backlog drains.

Still open. The retention window on the gateway store · backpressure when the buffer fills · whether camera stills ride the same buffer as the readings topic · which «Ternebåen» hardware revision becomes the reference gateway.
